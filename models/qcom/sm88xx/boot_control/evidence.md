# APSS boot control evidence

## Implemented model

The platform registers `qcom_vp::QcomApssBootScratch` from `apss_boot_scratch.h` as `qcom,apss-boot-scratch-v1`.
The implementation is header-only and uses the existing SystemC, CCI, and TLM conventions.
The socket accepts local offsets, not physical addresses.
Offsets `0x00..0x3c` hold sixteen little-endian, read/write, 32-bit scratch words.
Offset `0x38` holds the canary.
Unknown offsets return address errors. Unsupported commands, widths, and byte enables return errors.
The model provides no DMI, reset request, readiness state, or authentication result.

The board must explicitly supply `canary_reset` in the range `[0, 0xffffffff]`.
The default value exceeds that range and rejects elaboration.
No supplied evidence identifies the silicon reset value.
A board can select zero as a declared simulation initial condition, not as a measured reset state.
Firmware writes replace all 32 bits. Reads return the last written word.

The platform maps a page at `0x01fd4000` with `canary_reset = 0`.
The router supplies local offsets after the access monitor checks the transaction.
Other implemented words start at zero as explicit virtual policy.
They retain guest writes without creating debug metadata or authorization.

## Canary producer and consumer

Evidence comes from `pbl8850.bin`, mapped at `0x00300000`.
No firmware bytes are included here.

- PC `0x30d660` reads the canary before early fuse-controller selection.
- PC `0x30d6b0` checks that the canary did not change during that function.
- The function at `0x3056d8` calls initialization at `0x3094a4` and requests four generated bytes through `0x3094ec`.
- PC `0x305720` writes the generated word to `0x01fd4038`.
- The function pointer at `0x31a288` names `0x3056d8`. This is an indirect initialization path, not an unconditional direct call.
- Later protected functions read and compare this same scratch word. For example, `0x30da44` saves it and `0x30dad8` checks it.

The scratch model must not generate the canary. Firmware owns that write.
The earlier read requires an initial word, but does not establish its hardware reset value.

## Subsystem debug scratch

SM8845 XBL `0x1485c980` bounds the scratch index to `0..15`.
Its getter at `0x148794d8` accesses `0x01fd4000 + 4 * index`.
The corresponding SM8850 getter spans `0x1487ad94..0x1487adbc`.

The subsystem consumer requires header byte `0x81` before it parses debug options.
Cold-zero scratch therefore means no published options.
The model does not generate that header or change the consumer's decision.
SM8845 run37 passes the original index-three read before PMIC driver initialization.


## Subsequent scratch initialization

After the canary write, PC `0x305738` calls `0x3198f0`.
PC `0x319904` calls the descriptor initializer at `0x319968`.
PC `0x319934` conditionally calls it again after command 2 returns value 2.

The initializer iterates eleven 16-byte descriptors at `[0x31ec18, 0x31ecc8)`.
PC `0x319980` loads the destination address. PC `0x319984` loads the 32-bit value.
PC `0x319994` writes the value only when the destination is nonzero and the value differs from `0xdeadc0de`.
All eleven supplied descriptors have destination zero and value `0xdeadc0de`.
Therefore this ROM table establishes no additional implemented scratch registers.
Do not invent scratch writes from this generic initialization routine.

### Complete first-entry decision path

1. `0x427a7e` saves its registers and reads the external inhibit input.
2. `0x427aa6` calls legacy slot `0x308`.
3. Inhibit one, or startup class one or two, selects the bypass at `0x427cf0`.
4. Otherwise `0x427abc..0x427ad4` increments RAM counter `0x4480e4`.
   It writes `0xc0010000 | (counter & 0xffff)` to diagnostic word `0x00c04fe0`.
5. Firmware reads its own initialized byte at `0x4480f4`.

6. Eligibility calls legacy slot `0x3c0`.

9. The next calls are `0x437932`, `0x44223e`, and `0x442240`.

### Register and transition contract

All sockets use local offsets and aligned four-byte little-endian transactions.
Byte enables, missing data, short streaming widths, other widths, and unsupported commands return TLM errors and log a warning.
Unknown local offsets return address errors.
The model never grants DMI.

| Socket / physical range | Reset policy | Reads | Writes / effects |
| --- | --- | --- | --- |
| Inhibit / `0x00c0a000` | Zero, disconnected external input | Always zero | Rejected. No entropy, debug grant, or ready transition. |
| Vector / `0x00c00208` | Zero, no restored context | Last firmware-written word | Replace all bits. No CPU redirect, reset, or interrupt. |
| Diagnostics / `0x00c04fe0..0x00c04ffc` | Eight zero words | Last firmware-written word | Replace the addressed word. No queue or controller effect. |

Diagnostic producers establish all eight words.

Interrupt 29 uses `0x00c04fe8` at `0x427e94`.

The timer-related path uses `0x00c04ffc` at `0x427db8`.
The CLIC remains the interrupt owner. These diagnostic writes do not acknowledge interrupt sources.

Construction starts one cold virtual epoch.
Reads cause no transitions.
Only accepted vector and diagnostic writes change model state.
There is no warm-reset, collapse, resume, interrupt-injection, or debugger input API.
A CPU-only reset therefore cannot manufacture retained-context validity.
Unsupported surrounding hardware remains visible to the existing access monitor.
Authentication, rollback, AVB, and lock state are unchanged.

### Virtual control contract and security limits

The three control words start at explicit `policy_control_reset = 0`.
This declares no retained control programming at virtual construction.
No source supplied a physical reset measurement for these words.
A connected socket without an explicit 32-bit reset parameter rejects elaboration.
Each socket accepts only aligned, little-endian, four-byte reads and writes at local offset zero.
Malformed transactions and unknown offsets return the existing protection model's TLM errors.
No socket grants DMI.
Reads return the last accepted write.
Reads do not complete an operation or change state.
A CPU-only reset does not clear these words or reset the shared mode owner.

The control words are configuration retention substitutes.
Their complete silicon field names and side effects are not established.
They are separate from `DBGAR` at controller offset `0x304`.
Writes do not grant debug access, modify ordinary permissions, unlock regions, or disable an existing protection port.
Mode and control words do not replace lifecycle, fuse, serial-binding, authentication, or rollback checks.
The canary and subsystem scratch remain under `QcomApssBootScratch`, without another mapping or backing bank.

The [public Qualcomm access-control description](https://docs.qualcomm.com/doc/80-70020-11/topic/features.html#section-access-control-features) distinguishes xPU region authorization from other security mechanisms.
It supplies no register encoding or reset evidence for these four words.
The implementation therefore preserves the existing authorization checks instead of inferring a new permission grant from the control values.

### Hardware mutex for software ticket allocation

Both images contain two bank bases: `0x18860000` and `0x18861000`.
The acquisition helper selects a bank with identifier bits 15:8 and a word with bits 7:0.
It writes an owner, reads the result, and repeats until the result equals that owner.
The owner encodes `(cpu_ordinal & 0xff) | ((identifier & 0xffff) << 8) | 0x02000000`.
Release writes zero and reads the word again.

| Image and execution level | Bank table | Acquire helper | Owner store | Release helper |
| --- | --- | --- | --- | --- |
| SM8850 EL3 | `0xd8226448` | `0xd821ba9c` | `0xd821bad4` | `0xd821baf4` |
| SM8845 EL3 | `0xd8223460` | `0xd8218e88` | `0xd8218ec0` | `0xd8218ee0` |
| SM8850 secure EL1 | `0x157f94f8` | `0x157b767c` | `0x157b76b4` | `0x157b76d4` |
| SM8845 secure EL1 | `0x157eccc0` | `0x157adf18` | `0x157adf50` | `0x157adf70` |

Every identified direct caller supplies identifier one.
The EL3 callers acquire at `0xd821ba4c` and `0xd8218e38`, then release at `0xd821ba64` and `0xd8218e50`.
The secure EL1 callers acquire at `0x157b762c` and `0x157adec8`, then release at `0x157b7644` and `0x157adee0`.
Each caller protects the allocation of a software ticket, not the entire software critical section.
The firmware then waits for its ticket in ordinary memory.

The platform reuses `qcom,smem-mutex-v1` at `0x18860004` for all APSS cores and both execution levels.
The existing owner starts at zero, accepts a nonzero claim only while free, and retains the winner during contention.
A zero write releases the owner. Reads return the actual owner.
Plain write retention would not serialize competing ticket allocations.
The model does not replace the firmware's software locks or authentication decisions.
SM8845 run133 passes the EL3 mutex operation and enters QSEE at EL1.
Its trace records `Exception return from AArch64 EL3 to AArch64 EL1 PC 0x14694000`.
The executed `eret` is at `0x1468e2dc`.
The bootstrap programs `SCR_EL3 = 0x30e00`, with `NS=0`, and `SPSR_EL3 = 0x1c5`, selecting EL1h.
The same trace later records the EL3 return to `0x157b6b68` after a genuine SMC.
These observations do not establish UEFI, Linux, or authentication qualification.

## QSEE PDC configuration

`QcomApssPdc` owns the selected APSS PDC aperture at `0x0b200000`.
The firmware configures BCM controls, ownership bitmaps, event selection, and timestamp handoff words.
No capture source or wake source connects to this virtual controller.
Both runtime profiles therefore declare zero capture slots.
This declaration describes the virtual topology, not measured silicon.

SM8850 descriptor `0x157f2ba8` links this PDC to RSC base `0x18900000`.
Its capture-count read uses PDC offset `0x1004`, bits 15:12.
The native initializer accepts zero capture slots.
Capture enables use `0x4f00 + 0x14*index`.
Capture valid, low, and high words use `0x1200`, `0x1204`, and `0x1208` with the same stride.
Configuration cannot create a valid capture or a timestamp.

| Register group | PDC-relative offsets | Behavior |
| --- | --- | --- |
| BCM controls | `0x5504..0x5514` | Five independent retained words |
| Ownership bitmap | `0x4600..0x4614` | Six retained words |
| Owner | `0x4640` | Retained value, separate from the bitmap |
| Event selection | `0x48` | Retained selection, without an event |
| Comparison and handoff | `0x38`, `0x40`, domain stride `0x10000` | Four independent domain pairs |
| Capture registers | Per-slot words described above | Read-only zero without a producer |

SM8850 count words at `0x157d0698` select 180 records from `0x157f2298`.
SM8845 count words at `0x157c72b8` select 192 records from `0x157e5858`.
Both tables assign owner two except at indexes two, four, and six.
Both fit the six bitmap words.
The firmware retains its owner comparison and incompatible-owner failure path.
The model does not grant access or produce an interrupt from an ownership write.

The native fixture configures one advertised but disconnected capture slot.
Ownership, comparison, event selection, and capture enable do not produce a timestamp.
